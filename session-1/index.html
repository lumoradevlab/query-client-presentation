QueryClient

QueryClient: یک map از key به جعبه

@Singleton class QueryClient { val entries = ConcurrentHashMap<String, QueryEntry>() fun getOrCreate(key: String) = entries.computeIfAbsent(key) { QueryEntry(key) } }

Three tools

screen فقط سه ابزار لازم دارد

READ

useQuery

«این data را می‌خواهم.» key + یک fetcher. cache و refetch و retry با خودش.

WRITE

useMutation

«این را عوض کن.» خرید، ویرایش، حذف. بعد از موفقیت keyهای مربوط را invalidate می‌کند.

RENDER

QueryContent

«وقتی رسید، این را نشان بده.» loading و error را خودش می‌کشد.

A hook, line by line

یک hook، خط به خط

@Composablefun useHeadlines(source: String, page: Int = 1) : QueryResult<List<Article>> { val provider = hiltViewModel<HookProvider>() return useQuery( key = ArticleKeys.headlines(source, page), fetcher = { provider.articleRepository .getHeadlines(source, page) }, )} // the screenval headlines = useHeadlines("techcrunch")QueryContent(headlines) { ArticleList(it) }
1 · THE HOOK

یک تابع @Composable که UI نمی‌کشد؛ یک مقدار برمی‌گرداند. اسمش با use شروع می‌شود.

2 · HOOKPROVIDER

راه رسیدن به repositoryهای Hilt از داخل Compose. یک @HiltViewModel بدون state و بدون منطق.

3 · KEY

کدام جعبه؟ "articles.headlines.techcrunch.1". source و page در key هستند چون نتیجه را عوض می‌کنند.

4 · FETCHER

جعبه را از کجا پر کنیم؟ یک lambda که repository را صدا می‌زند؛ data برمی‌گرداند یا throw می‌کند.

5 · THE SCREEN

دو خط. hook جعبه را می‌دهد؛ QueryContent وقتی data رسید لیست را نشان می‌دهد.

QueryState · QueryContent

جعبه همیشه در یکی از سه حالت است

Loading
Success
Couldn't load
Retry
Failure

یک sealed interface؛ سه حالت، نه هشت ترکیب از سه boolean. QueryContent برای هر حالت یکی از این‌ها را می‌کشد.

useMutation · invalidate

write: بعد از خرید، همه‌جا عوض می‌شود

val buy = useMutation<BuyRequest, Order>( mutationFn = { req -> repo.buy(req) }, options = MutationOptions( invalidateKeys = listOf( WalletKeys.balance("USDT")), ), ) Button(onClick = { buy(request) }) { Text("Buy") }
1 · BUY

request به سرور؛ سفارش ثبت شد.

2 · INVALIDATE

جعبه‌ی wallet.balance.USDT «کهنه» علامت می‌خورد.

3 · REFETCH

هر screen که موجودی را نشان می‌دهد، خودکار تازه می‌شود.

screen خرید نمی‌داند screen کیف پول وجود دارد. فقط می‌گوید کدام data عوض شد.
