بخش اول Where it comes from

React Query

قبل از هر خط کد اندرویدی: این ایده در دنیای وب چه مشکلی را حل کرد، و چرا به Compose می‌آید.

قبل از React Query Redux era · ~2019

مشکلی که وب داشت

// Redux — one request, by hand
dispatch({ type: 'ARTICLES_LOADING' })
try {
  const data = await api.getHeadlines(source)
  dispatch({ type: 'ARTICLES_SUCCESS', data })
} catch (e) {
  dispatch({ type: 'ARTICLES_FAILURE', error: e.message })
}

function articlesReducer(state, action) {
  switch (action.type) {
    case 'ARTICLES_LOADING':
      return { ...state, isLoading: true, error: null }
    case 'ARTICLES_SUCCESS':
      return { ...state, isLoading: false, articles: action.data }
    case 'ARTICLES_FAILURE':
      return { ...state, isLoading: false, error: action.error }
  }
}

useEffect(() => { loadArticles() }, [])

آشنا نیست؟

action + reducer + isLoading در وب همان UiState + ViewModel + load() ماست، و useEffect همان LaunchedEffect.

و همان مشکل‌ها

  • کد تکراری برای هر درخواست
  • داده‌ی کهنه، بدون کش واقعی
  • درخواست تکراری از چند کامپوننت
  • صفحه‌ای که بعد از ویرایش تازه نمی‌شود
ایده TanStack Query · Tanner Linsley

داده‌ی سرور state نیست؛ کش است

// React Query
const { data, isLoading, error } = useQuery({
  queryKey: ['articles', source, page],
  queryFn: () => api.getHeadlines(source, page),
})

const bookmark = useMutation({
  mutationFn: (id) => api.bookmark(id),
  onSuccess: () =>
    queryClient.invalidateQueries({ queryKey: ['bookmarks'] }),
})

کامپوننت فقط می‌گوید «چه داده‌ای» و «از کجا». بقیه کار با یک QueryClient مرکزی است.

یک کش مرکزی، یک بار و درست

  • کش با کلید، مشترک بین کامپوننت‌ها
  • حذف درخواست‌های تکراری
  • stale-while-revalidate: داده‌ی قبلی را نشان بده، پشت صحنه تازه کن
  • retry، تازه‌سازی دوره‌ای و invalidate بعد از نوشتن
  • پاک کردن داده‌ای که کسی نگاهش نمی‌کند

کامپوننت دیگر داده‌ی سرور را «مدیریت» نمی‌کند؛ فقط آن را «درخواست» می‌کند.

بخش دوم The problem

یک صفحه‌ی ساده، این همه کد

بیشتر صفحه‌های ما فقط داده‌ای را از سرور نشان می‌دهند. اما برای هر کدام یک ViewModel، یک UiState و یک load() می‌نویسیم.

مقایسه MVVM vs hooks

همان صفحه، دو روش

روش معمول · MVVM~30 lines
data class HeadlinesUiState(
    val isLoading: Boolean = false,
    val articles: List<Article> = emptyList(),
    val error: String? = null,
)
@HiltViewModel
class HeadlinesViewModel @Inject constructor(
    private val repo: ArticleRepository,
) : ViewModel() {
    private val _state = MutableStateFlow(HeadlinesUiState())
    val state = _state.asStateFlow()

    fun load() = viewModelScope.launch {
        _state.update { it.copy(isLoading = true, error = null) }
        runCatching { repo.getHeadlines() }
            .onSuccess { l -> _state.update { it.copy(isLoading = false, articles = l) } }
            .onFailure { e -> _state.update { it.copy(isLoading = false, error = e.message) } }
    }
}
@Composable
fun HeadlinesScreen(vm: HeadlinesViewModel = hiltViewModel()) {
    val state by vm.state.collectAsStateWithLifecycle()
    LaunchedEffect(Unit) { vm.load() }
    when {
        state.isLoading -> Loading()
        state.error != null -> ErrorView(state.error!!, onRetry = vm::load)
        else -> ArticleList(state.articles)
    }
}

@Composable
fun useHeadlines(source: String, page: Int = 1)

وضعیت QueryState

یک وضعیت، فقط سه حالت

sealed interface QueryState<out T> {
    data object Loading : QueryState<Nothing>
    data class Success<out T>(
        val data: T,
        val refreshing: Boolean = false,
    ) : QueryState<T>
    data class Failure(val error: AppError) : QueryState<Nothing>
}
when (state) {
    is QueryState.Loading -> AppLoading()
    is QueryState.Failure -> AppErrorState(state.error.message, onRetry)
    is QueryState.Success -> content(state.data)
}   // ← this is QueryContent

internal fun isRetryable(t: Throwable): Boolean = when (t) {
    is IOException -> true                 // no connection
    is HttpStatusException -> when (t.httpStatusCode) {
        NETWORK_ERROR_CODE -> true
        408 -> true                        // timeout
        in 500..599 -> true                // server error
        else -> false                      // 4xx: same error again
    }
    else -> false
}
// 429 is handled in the network layer, with backoff

hook یعنی «یک قرارداد»

برای صفحه فرقی ندارد داده از REST با کش می‌آید یا از WebSocket: یک تابع useX() صدا می‌زند و مقدار می‌گیرد.

چرخه‌ی عمر در خود hook

اتصال در پس‌زمینه می‌خوابد و با برگشت کاربر دوباره وصل می‌شود؛ هیچ صفحه‌ای لازم نیست این را بداند.

آفلاین useCachedQuery · Room tier

وقتی داده باید بماند

val profile = useCachedQuery(
    key     = ProfileKeys.PROFILE,
    fetcher = { api.getProfile() },   // network -> ProfileEntity
    reader  = { dao.observe() },      // Room -> Flow<ProfileEntity?>
    writer  = { dao.upsert(it) },
)   // default: QueryOptions.OfflineForever
  • Room منبع حقیقت است: مقدار از reader می‌آید و هر fetch موفق با writer ذخیره می‌شود
  • بعد از بسته شدن اپ (process death) و بدون اینترنت هم داده هست
  • پیش‌فرض OfflineForever: خودبه‌خود کهنه نمی‌شود؛ فقط با invalidate تازه می‌شود
  • اگر fetch شکست بخورد، همان مقدار ذخیره‌شده نمایش داده می‌شود
  • وقتی کسی نگاه نمی‌کند، اشتراک Room هم قطع می‌شود

بیشتر کلیدها حافظه‌ای‌اند (useQuery). لایه‌ی Room فقط برای داده‌ای که واقعاً باید آفلاین بماند.

  • فرم و اعتبارسنجی (ورود، ثبت‌نام، برداشت)
  • جریان چندمرحله‌ای (KYC، تبدیل، خرید سریع)
  • state محلی که باید از تغییر configuration جان سالم به در ببرد

نه، فقط hook

  • صفحه‌ی فقط‌خواندنی، لیست، جزئیات
  • داده‌ای که چند صفحه مشترک می‌بینند
  • هر چیزی که فقط «بگیر و نشان بده» است

state holder خودش fetch نمی‌کند. state صفحه و اعتبارسنجی را نگه می‌دارد و همان hookها و mutationها را صدا می‌زند — نه یک راه دوم برای گرفتن داده.

موتور بدون Compose تست می‌شود

۱۲ تست موتور

  • serves cache within staleTime
  • de-duplicates concurrent reads
  • runs fetcher once across threads
  • persistent tier survives failed fetch
  • retries transient, not 4xx
  • skips a tick on a running fetch
  • evicts unobserved slots
  • invalidate forces a refetch
@Test
fun `concurrent reads are de-duplicated to a single fetch`() =
    runTest(UnconfinedTestDispatcher()) {
        val gate = CompletableDeferred<Unit>()
        var fetches = 0
        val entry = QueryEntry(
            key = "headlines",
            fetcher = { gate.await(); "value-${++fetches}" },
            staleTime = 0L,
            cacheTime = Long.MAX_VALUE,
            scope = backgroundScope,
        )
        entry.observe()
        entry.fetch()
        entry.fetch()
        assertEquals(0, fetches)   // still gated

        gate.complete(Unit)
        assertEquals(1, fetches)
    }
